# GoCine
DOCUMENTO DO PROJETO GOCINE                                                                                16/11/2026 

Banco de Dados Supabase: 

A estrutura do banco de dados foi projetada em ambiente PostgreSQL para dar suporte a uma aplicação de catálogo, gerenciamento e avaliação de obras audiovisuais, operando de forma integrada com uma API externa de mídias. Para evitar a duplicação desnecessária de dados pesados, como sinopses, pôsteres e fichas técnicas, o banco local armazena apenas os identificadores únicos fornecidos pela API externa, concentrando seus esforços na persistência das informações dos usuários e de suas interações dentro da plataforma. 

O núcleo do sistema é representado pela tabela de usuários, responsável por armazenar as credenciais de acesso e os dados básicos de identificação, como nome, e-mail único, senha e a data de realização do cadastro. A partir dessa entidade central, estabelecem-se relacionamentos de um para muitos com as demais funcionalidades principais da aplicação, garantindo a integridade referencial por meio de chaves estrangeiras que vinculam cada ação ao respectivo perfil do usuário. 

As interações dos usuários com o catálogo são divididas em três tabelas específicas vinculadas ao perfil. A tabela de avaliações registra as notas numéricas e os comentários textuais atribuídos aos filmes, acompanhados da data de publicação. Para o controle de consumo, a tabela de watchlist funciona como uma lista de interesse para títulos que o usuário deseja assistir futuramente, enquanto a tabela de histórico mantém o registro cronológico das obras que já foram visualizadas. Em todas essas estruturas, o controle temporal é registrado automaticamente por meio de marcações de data e hora com fuso horário. 

Por fim, o banco conta com a tabela auxiliar denominada user library, destinada à organização flexível de diferentes tipos de mídias em listas personalizadas. Diferente das tabelas anteriores, essa estrutura armazena o identificador do item, sua tipagem e o nome da lista correspondente de forma independente, permitindo categorizações variadas dentro da biblioteca do sistema sem vínculo direto por chave estrangeira no esquema atual. 

 

Front-End: 

O GoCine é um aplicativo web que desenvolvi para buscar, catalogar e organizar filmes e séries, funcionando como um guia pessoal parecido com o Letterboxd ou o IMDb. O foco do projeto não é transmitir vídeos completos — até porque isso envolve direitos autorais e licenças milionárias com os estúdios —, mas sim demonstrar na prática o consumo de APIs externas e o gerenciamento de dados do usuário, exibindo metadados oficiais como pôsteres, sinopses, notas, gêneros e onde assistir cada título. 
Para a identidade visual, criei uma interface moderna e responsiva utilizando HTML, Tailwind CSS e ícones da biblioteca lucide, apostando em um tema escuro com fundo preto e detalhes em vermelho para dar destaque ao catálogo. Durante o desenvolvimento, organizei o projeto na estrutura padrão de arquivos separados (index.html, styles.css e app.js) para facilitar a manutenção e a execução no VS Code. 
A integração dos dados passou por algumas etapas importantes até chegar à versão final. Comecei testando a API do TMDb (The Movie Database), que exige uma chave de acesso gratuita e entrega todo o conteúdo nativamente em português. Também implementei uma alternativa usando a API pública do TVMaze — que não precisa de chave e funciona diretamente no navegador sem bloqueios —, criando um dicionário interno em JavaScript para traduzir os títulos, gêneros e sinopses principais para o português. Em ambas as versões, apliquei um filtro rigoroso no código para garantir que apenas produções com capas oficiais válidas fossem exibidas na tela. 
Nas funcionalidades, implementei uma barra de pesquisa em tempo real com atraso inteligente (debounce) para evitar requisições excessivas enquanto o usuário digita, além de um modal interativo que abre ao clicar em qualquer capa para mostrar os detalhes completos da obra. Para que o usuário possa organizar o que consome, criei abas separadas para Catálogo, Curtidos, Já Assisti e Pretendo Assistir. 
Por fim, decidi utilizar o armazenamento local do próprio navegador (localStorage) para salvar todas as listas e preferências do usuário automaticamente. Dessa forma, dispensei a criação de uma tela de login ou de um banco de dados complexo em PHP nesta etapa, mantendo o código leve, rápido e 100% funcional para uso e apresentação. 

 

Back-End Segurança da API: 

A arquitetura de backend desenvolvida estabelece uma base sólida, moderna e segura para o funcionamento de aplicações web em PHP, integrando a comunicação com o banco de dados, a proteção contra ataques cibernéticos e a organização das regras do sistema. Todo o processo começa com a configuração da conexão através do PDO (PHP Data Objects), que atua como uma camada intermediária inteligente entre o código e o banco de dados; nessa etapa, definimos parâmetros rigorosos para que o sistema trate falhas por meio de exceções internas, registrando erros nos arquivos do servidor sem jamais expor detalhes técnicos sensíveis na tela do usuário, além de forçar o processamento nativo das instruções no banco. 
 
Essa preparação na conexão viabiliza a principal camada de defesa do sistema contra ataques de SQL Injection, uma vulnerabilidade crítica onde invasores tentam inserir comandos maliciosos dentro de formulários para roubar ou destruir informações. Para neutralizar esse risco, substituímos a concatenação direta de textos pelo uso de Prepared Statements (Consultas Preparadas), uma técnica em que o comando SQL é enviado e compilado pelo banco de dados utilizando marcadores isolados antes mesmo de receber os dados digitados pelo usuário, garantindo que qualquer tentativa de código malicioso seja interpretada estritamente como texto comum e inofensivo. 
 
Com a comunicação protegida, implementamos o sistema de autenticação e controle de sessões, responsável por gerenciar o acesso dos usuários de forma confiável. Nesse fluxo, as senhas nunca são armazenadas em texto puro, mas sim verificadas através de algoritmos de hash criptográfico (password_verify), garantindo que as credenciais permaneçam ilegíveis mesmo em caso de vazamento do banco. Além disso, no exato momento em que o login é aprovado, o sistema regenera o identificador da sessão do navegador (session_regenerate_id), uma medida preventiva essencial para impedir que invasores sequestrem sessões ativas de outros usuários. 
 
Por fim, toda essa estrutura de segurança dá suporte às regras de negócio aplicadas ao CRUD (as operações fundamentais de criar, ler, atualizar e apagar registros). Antes que qualquer informação seja gravada definitivamente, o código atua como um filtro rigoroso: primeiro, verifica se o usuário possui autorização ativa na sessão para executar aquela ação; em seguida, realiza a limpeza e validação dos dados recebidos, removendo espaços desnecessários e confirmando se formatos como e-mails são válidos; e, por último, executa validações lógicas diretamente no banco — como checar se um registro já existe para evitar duplicidades — assegurando que o banco de dados permaneça íntegro,organizado e livre de inconsistências. 

 

Back-End: 

Durante o desenvolvimento e a depuração da aplicação web GoCine — um catálogo de filmes e séries integrado à API do TMDb e a um backend em PHP com banco de dados SQLite — foi realizada uma revisão completa na estrutura HTML, na lógica de requisições JavaScript e na integração com o ambiente do servidor. Inicialmente, foram corrigidas falhas estruturais na interface, como o fechamento incompleto do atributo class da tag <body> (que havia sido cortado em selection e foi devidamente finalizado) e a tag de fechamento </header>, que estava quebrada entre linhas (</he e ader>) e comprometia a organização visual da página. Todos os demais componentes, incluindo o modal de configuração da chave de API, a barra de pesquisa em tempo real, a grade dinâmica de cartões e o modal de detalhes, foram validados para garantir o funcionamento correto da interface. Na camada de lógica em JavaScript, o consumo de APIs foi aprimorado com a implementação da função auxiliar fetchComTimeout, utilizando AbortController para limitar o tempo de espera das requisições a oito segundos, enviando o cabeçalho 'Accept': 'application/json' e tratando falhas de rede e erros de status HTTP. Também foram corrigidos problemas pontuais de sintaxe e lógica, como o ajuste do parâmetro options = {} na função de timeout, a padronização da constante headers, o uso correto de crases nas mensagens de erro, a grafia exata de 'AbortError', a separação da função fetchServerLibrary() que havia ficado presa em uma linha de comentário, a conversão numérica dos identificadores com Number() para evitar falhas de comparação entre strings do banco de dados e números da API, e a substituição do carregamento sequencial de favoritos por requisições paralelas com Promise.all para melhorar o desempenho. Por fim, na análise do erro Erro ao salvar (Unexpected token '<', " exibido pelo editor online, identificou-se que a abertura da tag <?php sem fechamento antes do HTML fazia o interpretador tratar a marcação como código PHP inválido e que as regras de segurança do servidor bloqueiam o salvamento de arquivos .php contendo tags <script> e URLs externas, definindo-se assim a separação entre o arquivo index.php (dedicado exclusivamente à API PHP/SQLite) e a interface frontend em HTML e JavaScript. 

Conclusão: 

O desenvolvimento do projeto GoCine consolida na prática a integração entre uma interface moderna, o consumo resiliente de APIs externas e uma arquitetura de backend estruturada e segura. Mais do que um simples catálogo digital, o sistema foi concebido como um guia pessoal completo para os amantes de cinema e séries, permitindo que o usuário pesquise títulos oficiais, consulte sinopses e fichas técnicas, avalie as obras assistidas com notas e comentários e organize sua rotina de entretenimento de forma prática nas listas de Curtidos, Já Assisti e Pretendo Assistir (Watchlist). 

Ao unir a agilidade do front-end construído com HTML, Tailwind CSS e JavaScript — equipado com busca inteligente, carregamento paralelo e controle de tempo limite nas requisições — à solidez do gerenciamento de dados com persistência e boas práticas de segurança no servidor (como consultas preparadas e validação rigorosa de registros), o GoCine entrega uma experiência fluida, responsiva e confiável. Dessa forma, o projeto atinge seu objetivo principal de demonstrar o ciclo completo de uma aplicação web funcional, oferecendo ao usuário controle total sobre seu histórico e suas preferências audiovisuais.
